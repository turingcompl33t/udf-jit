### Notes

In our UDF implementation, we need to answer the question: What SQL queries can we execute within the context of a UDF? Under what conditions? In other words, I need to familiarize myself with the current state and limitations of our UDF implementation.

Some systems / research with which I need to familiarize myself:
- MonetDB
- SQLite
- MemSQL / SingleStore
- HyPer / Umbra

These are, as far as we can tell, the systems that are doing some form of query compilation with code generation.

Andy thinks that a viable dissertation topic might something along the lines of: what are the tradeoffs between UDF compilation and UDF inlining? There are a couple of interesting papers to write on this topic.

Soon we need to start looking at recreating some of the experiments that Tanuj performed in his thesis. This will at least give us a baseline and allow us to determine how difficult it is to go through the evaluation process, end-to-end. Furthermore, once we have accomplished this, we can start looking at what additional features and / or optimizations we _need_ in order to perform the evaluation.

Interesting discussion question: at what level do we apply optimizations for UDFs within a DBMS that employs code generation? There are a couple of different options for this:
- Input PL/pgSQL (or alternative procedural extension to SQL)
- Query optimizer (does this make sense? can we optimize the embedded queries themselves?)
- Database DSL e.g. TPL (do we currently apply _any_ optimizations at the TPL level? If not, why not??)
- LLVM IR (this is easy, just set LLVM loose on the IR)
