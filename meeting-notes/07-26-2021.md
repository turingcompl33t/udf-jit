### Notes

I brought up the issues I ran into regarding the implementation of UDF code generation and it interaction with parallel table scans. Andy jumped on this and thought of some interesting potential for optimization research:
- Because we are doing code generation for UDFs, and we necessarily analyze the entirety of the UDF for which we generate code, we can integrate results from this analysis in the top-level query plan
- Specifically, do we want to allow queries embedded in UDFs to perform parallel table scans?
- This might not always be the most effective use of resources, while other times it might be
- Solution: push up the UDF analysis to the query optimizer and allow it to determine how it should allocate concurrency resources (e.g. threads) to the query; maybe it wants to parallelize the outer table scan and not the scan embedded in the UDF, or vice versa, or both, or neither
- Research area: auto-parallelization with embedded query logic

On the topic of the proposal: the thing that really matters for the proposal are the _ideas_ rather than the finer points of the procedure used in the preliminary results section. My focus needs to be on our ideas, their novelty, and their potential for productive research.
